# Hierarchical scientific workbench — approved implementation specification

The user approved implementation on 2026-10-03. Objects and blocks define scope; probes define presentation, checking, explanation and derivation; views display versioned evidence. Retain Python service, React workbench, CLI and desktop. Implement single-file synchronous Python now. Folder, cross-file and overlapping computation-stream providers are extension contracts with working development fixtures, not enabled product controls.

## Binding requirements

1. File/function/control/object tree and graph share selection. Click selects without opening documents or moving camera. Ctrl/Cmd toggles; Shift ranges and keyboard ranges; select-all includes matching offscreen rows. Parent selection deduplicates descendants. Enter/double-click/context menu explicitly navigate. Input and terminal shortcuts remain local. Dimming defaults off. Explicit scope entry updates browser, probes and results; collapse does not enter scope.
2. Separate semantic graph from source objects used for AI permission. Operations have named ports; nested function, branch and loop plates express data/control/call/return/merge/backedge relations. Structure/data/execution projections share original relation references. Scope symbols handle local shadowing, same-line statements, branch joins and loop-carried definitions. Dynamic/async/generator structures disclose coverage. Collapse aggregates relations without dangling edges. Worker compound layout uses measured geometry, pins and explicit direction; selection never relayouts.
3. Preserve synchronous Python semantics during control instrumentation. Branch suite entry records selected branch without reevaluating predicates. Loop counts mean body entries. Preserve short circuit, iterator evaluation, exceptions, break/continue/return and finally overrides. Per-activation counters and totals are bounded; retain at most 512 details/run and persisted cumulative summaries. Final receipt is necessary for complete counts; interrupted counts are lower bounds.
4. Probe taxonomy: targets (data/operation/function/control/file/project; folder/stream reserved), purpose (view/check/interpret/derive), implementation (builtin/program/model/skill/manual). Resource acquisition and instances are separate. Manifests declare targets/input roles/cardinality/parameter schema/output/evidence/version/dependencies/entry/examples. Catalog availability and local installation differ. Adapter drafts are reviewed before activation.
5. Metadata always visible; graph/table/analysis only from enabled bound presentation probes. A visible project default auto-view is created once; disable/delete/local exclusions persist across refresh/run/new versions. Restore is explicit. Manual probes independent, multiple views have instance-specific identity. Closing a document does not disable its probe. Hidden views stop expensive rendering. Third-party rendering/model/derivation requires execution. Selection/block/project scopes freeze concrete targets in plans.
6. Data semantics include matrix values/precision/labels/coordinates/units, table columns/index/missing formatting, plot mappings/series, graph groups. Validate coordinate lengths and track program/user/model origin. Templates reusable. Exact selected-cell value and zoom-aware numeric overlay; unsupported adapter parameters disabled.
7. Parallel comparison, relationship analysis and joint derivation have separate input roles. Elementwise operations default exact shape (explicit broadcasting); matmul, aggregation, correlation and key-based join validate types/shape/coordinates/missing policy. Exact joint operations require authorized complete artifacts with clear missing/expired/budget/coordinate diagnoses; never use sliced previews as full data. Targeted full capture creates a new run. Derived immutable objects retain parents and can bind probes/rederive/generate code proposals. Retention protects retained derived parents.
8. Shared versioned models/services/APIs and generated frontend types: logical identities vs evidence versions, graph/blocks, scope/selection, resource/instance/resolved invocation, semantics, derived data, control summaries and terminal sessions. Frozen definitions/resources/parameters executed without catalog re-resolution. CLI manages the same models. Structural parents vs overlapping stream member references remain distinct. AI control/containment edges do not widen context permissions.
9. Dockview replaces broken custom split geometry: drag tabs, horizontal/vertical resize, minimize releasing space, restore/maximize, named layouts and structural lock with designated new-view slots. Responsive CSS cannot cancel resizing. Run button/mode/scope separated and aligned. Searchable settings with user/project/instance source and reset; model entry remains direct. Tasks run/phase/invocation tree; results target/probe/status; events scope/type/time aggregation. Execution, quality and fidelity distinct.
10. xterm.js plus real shared PTY: Windows ConPTY via pywinpty; POSIX PTY. CLI/Python/shell project cwd; Unicode, dimensions, Ctrl+C, clipboard, multiple sessions and reconnect. Hidden retains; explicit end kills owned tree; owning service exit cleans sessions. Errors visible. Authenticate origin/session, bound output; no implicit model access.
11. Migration preserves backups/IDs/history/default deletion and reports ambiguous bindings; converts old layouts or leaves recoverable record. Legacy coordinate-incomplete tables cannot perform label-dependent operations. Eight complete success/failure examples: matrix, table, function, control, file, comparison/derivation, custom program, Skill.
