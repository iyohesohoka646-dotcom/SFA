# 0.5.1 工作台审查与修复

本次基于 `3dad30bb2adc857021cca4a4f409497ceb7e1172` 审查启动、对象与计算图、探针接入及绑定、数据视图、联合计算与反向代码、历史证据、设置、布局、终端、模型上下文、CLI 和安装交付。使用真实浏览器及 Electron 检查操作效果，并另行进行只读代码审查；确认的问题都有针对实际错误的回归用例。

## 启动入口与已确认缺陷

用户实际使用的桌面快捷方式指向已安装的 **0.3.0**；仓库此前验证的是 **0.5.0 打包程序**，没有同步该安装入口。正常启动时本次没有复现持续黑屏，因此不将版本落后单独认定为黑屏根因。资源加载失败、视图渲染异常、渲染进程崩溃和服务初始化失败的路径已分别复现并修复。

| 问题 | 修复和回归范围 |
| --- | --- |
| 主界面脚本加载失败后没有可用界面 | 独立启动脚本、错误状态和重试入口，不依赖失败的主 bundle |
| 视图渲染异常清空整个工作台 | 根与面板两层错误边界；其他视图和工具栏保持可操作 |
| 一个懒加载视图令整个工作区隐藏 | 各文档独立加载边界；阻塞真实图资源时仍可操作探针台 |
| 后台源码填充分屏时，已按下的设置按钮丢失点击 | 区分全局焦点与组内显示标签，不再重复激活已显示内容；后台加载保留当前分屏焦点，显式导航再切换焦点；在鼠标按下与抬起之间完成真实源码导入的回归通过 |
| 初始 API 请求失败后无法重试 | 显示失败状态，重试重新加载项目配置与对象 |
| 桌面渲染崩溃导致退出，失败导航没有恢复 | 原生恢复页面、服务重建、显式重试；丢失 IPC 状态通过权威状态查询补回 |
| 缺失 Python 的错误延迟六秒 | 按失败 spawn 的 close 生命周期清理 |
| 桌面“退出并停止”只停止 HTTP 服务 | 通过受来源校验的 IPC 关闭拥有窗口，并清理后台服务 |
| 缩小后重建终端界面，丢失无障碍设置及当前输出呈现 | 隐藏和切换标签保留终端界面及连接，关闭标签才释放前端连接；后台会话仍由显式结束和应用退出清理 |
| 探针用途筛选显示一个定义、却保存另一个定义 | 当前可见且兼容的定义决定保存内容 |
| 同一种探针第二次绑定失效，无选择时无法添加 | 消费每次绑定请求；无选择时使用当前块或项目范围 |
| 按设置分类搜索后表单字段消失 | 分类与字段搜索采用一致规则 |
| 内置函数、推导式局部变量被画成未知外部数据 | 词法读名处理推导式与 lambda；保留真实遮蔽的内置名称 |
| 旧 v2 分析缓存返回空结构 | 从相同摘要的存档重建，保留分析及可对应对象 ID，保存原始备份；无法核对的存档明确报错 |
| 历史源码下拉框查询当前分析、点击失效 | 源码文档传出其所属分析与对象 |
| 安装的自定义探针无法保存模板 | 参数验证复用当前工作台注册表，禁用资源仍不可启用 |
| 旧运行结果被全局最近 1000 项遮蔽 | SQL 中先筛选再分页；UI 提供显式读取更多结果，迟到响应不替换新运行 |
| 切换运行后续页按钮一直处于加载中 | 切换时重置分页状态，响应同时校验运行 ID 和请求代数；返回旧运行也可重新请求 |
| 展平相关分析的生成代码无法重现内核 | 先展平再检查形状；检验普通与成对缺失两种输入 |
| 重建发行包残留旧哈希资源，源码包遗漏启动资源的构建输入 | 清空构建缓存后打包，核对资源集合；源码包包含 `web/public` |

源码与私有 Python 的 243 个发行文件逐一核对。性能夹具包含 1,000 个逻辑对象、每个对象 10 个版本及 10,000 个事件；20 次选择的 P95 为 **2.8 ms**，图隐藏后为 **2.1 ms**。这项测量仅覆盖历史对象选择，不包含计算、冷启动或首次绘图。完整测量见 [性能记录](../assets/scientific-performance.json)，可公开的验收汇总见 [验证记录](../assets/workbench-audit-validation.json)。

实际桌面物理目录原有 1 次运行、50 个事件、12 个快照及 11 个计算记录，这次升级后仍可读取。开发 CLI 使用 Microsoft Store 版 Python，其 AppData 访问被系统重定向，另一份目录有 5 次运行；这份目录的所有原主键及源码也校验保留。两份数据分别备份，没有自动合并；备份包含本机状态，留在忽略提交的 `.work/installed-backup-*` 与 `.work/installed-physical-backup-*` 中。重定向行为见 [Python 官方文档](https://docs.python.org/3.10/using/windows.html#known-issues)。桌面配套 CLI 使用私有运行时，交互 CLI 也可通过 `--connect` 连接当前服务，共享它的历史。

打开原来的桌面快捷方式即可使用更新后的应用。设置中的“版本信息”应显示 `Scientific Dataflow Inspector 0.5.1`；启动失败现在会保留错误页和重试入口，面板失败不会清空整个工作台。

## 边界

在线模型服务的真实远程推理未调用；模型设置和工具循环使用离线模式与本地 HTTP 夹具验证。此轮原生验收面向 Windows，macOS/Linux 的 Python 和浏览器能力以对应 CI 为准，未新增原生安装包。NSIS 已实际静默安装，交互式安装向导未操作，安装包未签名。正常入口的持续黑屏未直接复现，已复现的四类启动失败分别提供回归证据；不将版本更新等同于确认所有黑屏原因。性能数据区分历史选择、布局和真实科学计算，不将局部延迟推广为所有实验的运行速度。

后台导入期间丢失点击现已可控复现：暂停首次源码响应，按下设置分类按钮后完成响应，再抬起鼠标。原生事件和调用栈显示，重复激活组内已显示标签会移除并重新插入 `dv-react-part`，同一按钮收到按下及抬起却没有点击；改为检查组内 `activePanel` 后，内容保持连接，点击与分类切换生效。探针库曾发生的单次丢失点击没有同样的原生事件记录，因此不把此调用栈当作那一次故障的直接证据；原资源目录操作与设置保存任务继续保留在完整回归中。测试没有增加重复点击或放宽效果断言。
