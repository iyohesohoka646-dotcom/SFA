# 普通 Python 分析脚本的观察范围

自动模式只在内存中处理用户选定的源码，保持原文件、Python 求值顺序与原 traceback 行号。没有全局替换 NumPy 函数，也没有在每行扫描全部变量。支持赋值、解包、分支、循环、普通函数、可见下标写入和常见原地修改；变量版本、操作执行次数和函数调用作用域分别记录。

操作输入来自执行前真实可见的绑定，输入与输出形状来自原生对象。表达式中的依赖边标为 `inferred`，不把名字出现当作逐元素依赖证明。规则解释可使用源码及真实维度，实验轴含义和物理单位仍需用户声明。

已知 NumPy 数组和视图采用弱引用跟踪共享存储。可见的原地修改会重新观察已确认共享内存的视图，过去的样例保持不变。别名候选超过 256 或共享内存判断超出预算会发布覆盖限制；隐藏在任意调用中的修改仍需显式 `watch`。结束的函数调用清理活跃采集状态，历史事件保留在收集服务。

下列情况有明确的覆盖诊断：

- `eval/exec/compile` 创建的代码、未选源码、原生扩展内部修改和多进程子任务无法自动保证覆盖。
- 生成器和异步函数的内部作用域首版不自动插桩，使用显式 SDK；不让生成器暂停时污染调用者作用域。
- 活跃外层函数中的 `nonlocal` 解析到外层作用域；脱离外层调用的闭包所有权只能按当前调用观察，标为覆盖不完整。
- 使用 `globals/locals/vars/dir` 或直接帧反射的脚本保持原样执行，自动模式提示改用显式 SDK，避免额外观察符号改变其计算。
- 类方法可观察，类定义体和自定义元类命名空间写入不做自动变换；属性内部状态与任意动态对象保持未知。

自动操作耗时在赋值完成后、采集之前截取，注明 `statement-only`。显式 SDK 的 `operation` 统计其整个上下文，注明 `scope-including-observation`，包含用户在范围内调用的观察操作。

完整矩阵、表格和探针不依赖于自动插桩。覆盖不足时可把 `TraceSession.watch` 放在关键值定义或修改之后，使用 `operation` 给出明确输入和操作含义。
