# 0.5.2 交互、图谱与探针改进

本轮在 `3e6882fca56343ab3b42668e61c3b9c5ac1776df` 上按截图反馈修复对象导航、探针配置、计算图和代码书写整理。保留本地 Python 服务、React 工作台、桌面与 CLI 共用的应用服务。

## 对象与源码

对象浏览器按文件夹、文件和源码位置组织。文件夹与文件用图标和展开箭头表示；默认只展开当前最大范围，后代可逐级展开，搜索自动显示匹配项所在路径。同一词法作用域的重复赋值合并为一个逻辑变量，显示最后一次实际观测值；展开可查静态赋值位置与运行版本。没有运行证据时只显示定义，静态代码中最后一行不冒充最终执行结果。

选中逻辑变量会标出该作用域内全部定义和使用，定义与使用采用不同强调方式。局部遮蔽、同名函数、类体先读后赋值、推导式、lambda、global/nonlocal 和函数签名中的绑定分别处理。Ctrl/Cmd、Shift 和全选共享对象树与图的选择状态；全选覆盖当前范围全部匹配对象，包括折叠和屏幕外对象，排除仅用于显示路径的祖先，沿用已加载的历史证据筛选。空筛选全选会清空旧选择。单击不跳转，双击、Enter 或右键菜单才导航。

## 探针配置

模型服务与模型列表在设置中统一保存；探针和智能任务直接选择已配置服务与模型。任务要求拆为任务指令、关注重点、约束和输出要求，实际执行时共同构成模型输入。显式选择一个服务但沿用其默认模型时，不会继承另一服务的模型名。

探针台在新建表单前，按所选对象逐项列出可折叠的有效探针，并区分本地绑定、继承和项目默认。未进入块时“当前块”采用当前文件范围。用途筛选只列兼容探针，避免空类别；探针库提供默认参数配置，后续新绑定继承，旧实例保留原参数。多对象移除绑定依据逻辑身份与词法作用域，最后赋值位置改变后仍能移除。同名函数重复定义下的局部覆盖区分各自作用域；源码更新后不能唯一恢复的旧对象绑定要求重新绑定，不扩大到另一处同名变量。块绑定保存稳定范围引用；书写整理后可恢复唯一对应块，歧义要求重新绑定。

## 图谱

“布局与关系”浮在画布上，Escape 或点击外部关闭。结构视图以计算单元、函数和控制底板为主；数据视图加入数据对象、类型与形状；执行视图叠加实际路径、状态和计数。缺少证据保持未观测，函数总次数不会代替每条调用边的次数。

折叠边界使用独立端口和简短条件、变量标签，保留原始关系引用。函数、条件、循环、调用、返回与不同数据形态采用颜色、图标和轮廓区分。画布支持左键或中键拖动、缩放、框选与 Shift 框选。选择、虚化和数据更新不触发布局；用户可以整理当前块、整理全部和改变方向。

ELK 使用真实节点尺寸、嵌套容器、独立输入输出端口及实际路由，长链可以换行。浏览器发现的空数据视图来自 ELK 0.11 在复合图中使用模型排序时的异常；关闭该排序路径，保留种子和交叉最小化，并用真实失败拓扑回归。布局完成后一次显示节点；模式或范围切换使用新布局定位，避免临时节点移动导致点击丢失。根层直接显示超过 160 个结构单元时也默认折叠，并显示实际折叠数量，保留全部内部关系；用户可以显式展开。首屏按实际画布尺寸采用 0.75–1 倍可读缩放，大图从起始区域显示；“适应画布”允许更小缩放以提供完整全景，折叠展开保留视角。

固定关系图保留原运行的采集证据与相机，切换全局运行后仍从原版本打开数据。实时状态尚未加载完成时继续使用已获取的历史证据。自动插桩的运行值和已完成语句正常呈现；记录中的 `provenance` 描述依赖来源，不作为值是否真实采集的判断。来源不明确或由解析推断的依赖仍显示为未确认路径，不冒充实际数据流次数。

运行分析按文件路径和源码摘要使用 SQLite 索引精确查询，不再读取整个分析库，也不受最近 1000 条记录的限制。数据面板复用当前运行已加载的分析；同一运行内切换数值版本、更新结果和保存配置不重新读取分析。固定旧运行按自己的版本缓存，迟到请求不会覆盖新运行。

设计与实现参考 [React Flow 子图](https://reactflow.dev/examples/grouping/sub-flows)、[多端口 ELK 布局](https://reactflow.dev/examples/layout/elkjs-multiple-handles)、[画布交互](https://reactflow.dev/learn/concepts/the-viewport)、[X6 连接桩](https://x6.antv.antgroup.com/en/tutorial/basic/port) 和 [ELK Layered](https://eclipse.dev/elk/reference/algorithms/org-eclipse-elk-layered.html)。当前继续使用 React Flow；这些参考用于分组、端口与交互设计。

## 智能书写整理

智能助手中的“整理代码书写”使用已配置的模型，读取当前导入文件并提出差异；只有人接受后才写入。计算语法树、研究注释、语句顺序、类型忽略注释所属语句和原编码均检查。新增导入、改计算、改签名、移动语句或不可编码的候选会被阻断。接受期间源码变化会产生冲突，回滚也经过独立提案和明确接受。

这项功能处理缩进、分行、空白和段落，不重写科学算法。源码行号可以变化，依赖行号的外部工具需要重新读取。单次完整文件提案上限为 16,384 字符；含凭据的源码不会进入整理模型上下文。CLI 同样可用 `cdaf workbench ask --format-source`，提案仍需审查。
